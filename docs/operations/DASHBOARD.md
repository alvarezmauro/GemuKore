# Private dashboard

The `/app` private collection overview uses the existing application shell. It includes Total items, Consoles, Games, Accessories, Boxed items, Items with active defects and Recently added, plus links to the established collection workflows. Task 17.1 establishes the UX and data contract; Task 17.2 consolidates and measures its database reads.

## Counts and recent copies

Counts describe owned `CollectionItem` copies, including multiple copies of one catalog identity and retained archived identities. Canonical catalog records without owned copies do not increase totals. Boxed items include only `hasBox=true`; unknown and false are excluded, and having a box does not imply completeness. Items with active defects include copies with at least one `ACTIVE` defect, counted once regardless of the number of defects. `ACCEPTED` and `REPAIRED` defects do not contribute. The link opens defect records without pretending the existing unresolved-defect filter matches this narrower metric.

Recently added shows the latest eight physical copies, ordered by creation time then copy UUID descending, with a ninth-row sentinel for the overflow notice. Each entry includes its copy link, catalog identity/context, category, date added and a thumbnail or explicit no-photo/unavailable fallback. Dates use a fixed English format and UTC to keep server/client output consistent; the page labels the timezone. An edited copy does not become a recent addition. All recent entries and links remain immediately available; there is no delayed reveal or looping notification feed.

After authorization, the service makes at most three data reads: one aggregate row for all six counts, nine recent identities including the overflow sentinel, and photos for the eight visible IDs. The empty collection skips the photo read. PostgreSQL computes category and box counts in one collection scan and counts distinct active-defect copy IDs in a once-only subquery. Recent IDs are limited before canonical identity hydration, with indexed subtype lookups. The photo-only batch shares the collection-card thumbnail policy without fetching unused producer or defect summaries. Collection rows are never loaded into application memory to count them, and there are no per-row database requests. Existing indexes suffice; see [query measurements and reproduction](../performance/DASHBOARD_QUERIES.md).

Statistics reflect the authorized request snapshot; there is no polling, background refresh or persistent cache. A copy deleted between count and recent reads remains consistently visible in that snapshot and disappears on the next request. Refresh overview requests a new snapshot while retaining current values, with a disabled pending control and a reduced-motion-aware skeleton status. It is a normal GET form when JavaScript is unavailable. There is no route-level streamed skeleton that would hide the resolved server content from a JavaScript-free browser.

## Access and privacy

`getDashboard` revalidates `private.read` and the current role within a Repeatable Read transaction. Returned flags use that current role, not a captured client role. The request adapter authenticates through the existing session/grant flow. Disabled/deleted grants and expired/deleted sessions deny further access. The route remains dynamic with private no-store responses.

The dashboard DTO includes only counts and bounded recent display identities, links, dates and safe private thumbnail URLs. It omits account identifiers, serials, private notes, locations, defect descriptions, storage locators, metadata snapshots and audit payloads. Recent thumbnails reuse the collection-card policy: ready display photos, excluding SERIAL and custom model/logo uses, with a thumbnail derivative when available. Media endpoints independently enforce authorization. No public query or endpoint is introduced.

Editors and administrators get add/manage links. Viewers get read-only labels and no creation or catalog-management controls. Existing destination services remain responsible for permission checks. The shell retains the role indicator, command palette, theme menu, collection links and sign-out. A failed read shows Overview unavailable with a retry; it never renders fabricated zero counts. A truly empty collection shows actual zeros and role-appropriate introductory guidance.

## Visual and motion behavior

The burgundy Bento layout places the illustrated collection hero and recent-copy cards beside category shortcuts and a circular total/category summary. Confirmed-box and active-defect counts remain available in the compact footer. It uses semantic server-rendered sections and shared theme tokens. Cards require neither hover nor animation to expose actions. The desktop dashboard fits the viewport; mobile uses natural document flow. Long card identities remain available through accessible copy links and their detail pages. The superseding visual direction is documented in `DESIGN.md` and Task 17.3 below.

The owned `NumberTicker` adapts the [Magic UI Number Ticker](https://magicui.design/docs/components/number-ticker) with the existing Motion runtime and short shared timing. The real formatted value is in server HTML and remains the accessible value throughout. The visual tween is finite, has no spring/delay and is skipped for unknown/reduced-motion preferences. Cleanup stops playback, restores the final value and rejects late callbacks when the preference changes. There is no per-frame React state update or live-region chatter.

The semantic [Bento Grid](https://magicui.design/docs/components/bento-grid) adaptation stays server-rendered. Recent cards use the existing `AnimatedList` equivalent documented in [Animation strategy](ANIMATION_STRATEGY.md), preserving static order/content, stable copy identities and live reduced-motion handling rather than the registry's delayed notification sequence. The [Magic UI Animated List](https://magicui.design/docs/components/animated-list) is the reference pattern. No extra UI or animation dependency is needed.

## Reference visual refresh — Task 17.3

The 2026-11-11 user-authorized visual refresh replaces the original neutral layout with the composition documented in `DESIGN.md`. Counts, the recent-copy DTO and database reads are unchanged. The dashboard presents all eight recent entries in an accessible horizontal carousel, with explicit previous/next controls and native keyboard focus scrolling; the most recent copy also appears in a compact latest row. All links and values are server-rendered. The full collection remains reachable through the section links.

The shared private shell fills the viewport width and at least its height, with internal content spacing and no outer card frame or width cap. The desktop dashboard fits the viewport from 1024px × 640px upward without suppressing document overflow. Mobile, short and effective zoomed viewports use normal page flow. Other application routes retain normal document scrolling. The role, confirmed-box count, active-defect count and refresh control are in the footer; sign-out and appearance are in the header; authorized creation links are in the rail's add-item menu. Category shortcuts open real filtered collection routes. Sample counts, user identity, shopping, favorites and notification features are not introduced.

The reference's hero artwork is displayed as a decorative CSS crop of the user-supplied source, separately from the existing authenticated photo pipeline. Number Ticker and Animated List retain their accessibility/static/reduced-motion guarantees. Section/ring entrance and hover effects are finite and disabled by reduced motion. See [asset provenance](../design/DASHBOARD_ASSETS.md).

Task 17.3 verification passes lint, typecheck, production builds, formatting and whitespace, all 1,493 unit/component cases, 34 dashboard/access integration cases and 26 distinct desktop/mobile browser cases across full and focused runs. The final focused rerun confirms the corrected search label and mobile search entry point, complete carousel navigation, all nine desktop fits and accessibility scans in both appearances.
